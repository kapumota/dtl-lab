\section{Introduction}
\label{sec:introduction}

Sharding is a common strategy for increasing the capacity of distributed ledgers by partitioning state and transaction processing across multiple shards. The resulting parallelism, however, introduces a coordination problem whenever a transaction spans more than one shard: the system must preserve a consistent terminal outcome even when messages are delayed or duplicated, quorum conditions are not met, or an execution is interrupted before all state changes are applied. Prior systems such as Chainspace, OmniLedger, Prophet, CSLAP, and LightCross illustrate different design points for cross-shard transaction processing and atomic commit \cite{albassam2018chainspace,kokoriskogias2018omniledger,hong2023prophet,du2024cslap,qi2024lightcross}. These mechanisms improve cross-shard execution, but their correctness arguments, implementation evidence, and evaluation methodologies differ substantially.

Formal methods provide one way to reason about protocol behavior beyond conventional testing. TLA+ and related model-checking workflows have been used to analyze distributed protocols and to connect formal models with executable systems \cite{schultz2025mongodb,cirstea2025traces,hackett2025tracelink,howard2025ccf,wang2023mocket,gao2025imocket}. Mutation-based assessment offers a different type of evidence by asking whether a specification or property suite reacts when selected protocol controls are intentionally weakened \cite{cordy2023mutation}. These techniques are complementary rather than interchangeable: bounded model checking evaluates the declared properties within finite configurations, mutation analysis evaluates sensitivity to controlled defects, and trace-conformance techniques evaluate whether selected implementation observations are admitted by a formal abstraction.

This paper studies an executable cross-shard commit protocol implemented in DTL-Lab, a research-oriented Java simulator rather than a production blockchain. The protocol coordinates source locking, receipt creation and delivery, destination preparation, commit, abort, timeout, rollback, replay protection, and quorum enforcement. Two bounded formal representations, in TLA+ and Alloy, capture the same protocol concerns through different state representations and exploration semantics. The study does not assume semantic equivalence between the two formal models, and it does not treat either tool as intrinsically superior.

The central methodological objective is to connect several forms of evidence under one frozen experimental protocol. Within the comparator set for which full text was verified in our structured review, we did not identify a cross-shard study that reports all of the following together: bounded property verification using complementary TLA+ and Alloy models, targeted mutation-based property validation, bounded implementation-model trace conformance over both valid and deliberately corrupted traces, explicit verification-cost characterization, and independent reproduction of the analytical artifact. This statement is deliberately limited to the reviewed comparator set and is not a priority claim about the complete literature. The contribution of this work is therefore an integrated and reproducible evidence workflow for an executable cross-shard protocol, rather than a claim that any individual technique is new in isolation.

The study is organized around four research questions:

\begin{description}
\item[\textbf{RQ1.}] What bounded property-verification outcomes are obtained for the valid TLA+ and Alloy models across the declared experimental configurations?

\item[\textbf{RQ2.}] Do the evaluated TLA+ and Alloy properties detect predefined scientific mutations that remove selected protocol controls?

\item[\textbf{RQ3.}] Do selected valid and deliberately corrupted Java executions satisfy the expected bounded implementation-model trace-conformance outcomes under the declared projection and scenario catalogue?

\item[\textbf{RQ4.}] How does verification cost vary across the evaluated bound profiles and TLC fault profiles under the frozen execution protocol?
\end{description}

The evidence produced for these questions is intentionally layered. RQ1 provides bounded property verification and records both completed and censored configurations. RQ2 evaluates mutation-based property validation against a predefined catalogue of scientific mutants. RQ3 evaluates bounded implementation-model trace conformance and does not constitute a general refinement proof or behavioral equivalence between Java and either formal specification. RQ4 characterizes verification cost within the evaluated tools and profiles; it does not establish an asymptotic complexity law or support absolute TLC-versus-Alloy performance claims.

The definitive campaign scheduled 1,272 tasks. For RQ1, 420 measured executions were scheduled, 350 completed, and 70 TLC-large executions were censored by timeout; no property violations were observed among the completed configurations. For RQ2, all 10 predefined scientific mutants were detected, yielding a mutation score of 1.0 for the evaluated catalogue. For RQ3, 600 executions covered valid and deliberately corrupted trace populations, with the valid population accepted and the corrupted population rejected with the expected diagnostics. RQ4 shows increasing verification cost across the completed Alloy bound profiles, while all measured TLC-large executions reached the timeout threshold. These observations support bounded and tool-specific conclusions only; they do not provide an unbounded correctness proof or a nonlinear scaling law.

Reproducibility is treated as a separate evidence layer. The analytical artifact was exercised from a separate clone and execution workspace under a separate operating-system user on the same native Linux host. The successful reproduction completed 10/10 predefined gates and reproduced 32/32 expected analysis-artifact hashes. This establishes process separation and deterministic reconstruction of the preserved analytical outputs under the documented environment, but not hardware independence, a complete rerun of all 1,272 tasks, or scientific correctness from hash agreement alone.

The remainder of the paper is structured as follows. Background and Related Work positions the study relative to cross-shard protocols, formal analysis, mutation-based specification assessment, and implementation-model conformance. The Cross-Shard Transaction Model then defines the executable protocol and its bounded formal abstractions. The methodology and frozen experimental design are presented next, followed by the results, discussion, threats to validity, and reproducibility evidence.
